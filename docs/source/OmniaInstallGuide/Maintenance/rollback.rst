Rollback Omnia
===============

This section describes how to rollback to a previous version of Omnia core container.

.. note::
    Rollback is supported from Omnia 2.2.0.0 to 2.1.0.0. Ensure you have a valid backup of the 2.1.0.0 configuration before proceeding.

Rollback to the previous version
--------------------------------

To rollback to a previous version of Omnia core container, run the following command: ::

    ./omnia.sh --rollback

Select the previous version and confirm to proceed. A message confirming the rollback is successful is displayed.

Post-Rollback Status
--------------------

The ``Omnia_core`` container runs with inputs and configurations restored from backup.

To view the Omnia version, run the following command: ::
    
    ./omnia.sh --version

BMC Discovery Rollback Considerations
--------------------------------------

When rolling back from a version that includes BMC Discovery configuration, the following considerations apply:

Configuration Files
~~~~~~~~~~~~~~~~~~~

The rollback process restores the following BMC Discovery-related files from backup:

* ``input/discovery_config.yml`` - OME IP configuration
* ``input/omnia_config_credentials.yml`` - OME credentials (Ansible Vault encrypted)
* ``input/network_spec.yml`` - Network configuration used for IP address derivation

These files are restored to their state at the time of the previous version backup.

OME Credentials
~~~~~~~~~~~~~~~

The Ansible Vault-encrypted OME credentials file (``omnia_config_credentials.yml``) and its vault key (``.omnia_config_credentials_key``) are restored from backup. If you have changed OME credentials after the upgrade, you may need to:

1. Re-run ``prepare_oim`` to update the credentials in the Ansible Vault
2. Verify the credentials are valid for the rolled-back version

PXE Mapping Files
~~~~~~~~~~~~~~~~~

The timestamped PXE mapping files generated by BMC Discovery (``bmc_pxe_mapping_file_<timestamp>.csv``) are preserved during rollback. However, consider the following:

* If the rolled-back version does not support BMC Discovery, you may need to manually create or regenerate the ``pxe_mapping_file.csv`` using the appropriate method for that version
* If you have added or removed servers after the upgrade, review the PXE mapping file to ensure it reflects the current server inventory
* For incremental updates, you may need to re-run BMC discovery after rollback to ensure the PXE mapping file is up-to-date

Re-running BMC Discovery After Rollback
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

If you need to re-run BMC discovery after rollback, ensure that:

1. The OME appliance is still operational and reachable on port 443
2. The ``discovery_config.yml`` contains the correct OME IP address
3. OME credentials are properly configured (re-run ``prepare_oim`` if needed)
4. The ``network_spec.yml`` is configured with the correct admin and IB subnet information

Then run the discovery playbook:

.. code-block:: bash

    ansible-playbook discovery/discovery.yml -e "discovery_mechanism=ome"

.. note::
    Magellan-based discovery is planned for a future release. Currently, only OME-based discovery is supported.
